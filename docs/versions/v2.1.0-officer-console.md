# v2.1.0-officer-console: the officer console as the one screen

**Tag:** `v2.1.0-officer-console` · **Date:** 2026-09-24 · **Status:** frozen · **Current release**

This builds on [v2.0.0-console](v2.0.0-console.md), with the same server, shared services, models and offline behaviour. The home page at `http://localhost:8080` is now **the forest-officer console** (Kruthika's incident map). It has the map, incidents, Live watch, Ask Sentinel, the guided scenarios, **Report sighting** and the **Simulate outage / Restore link** control. It also gains the parts of the earlier apps it did not have, as tabs in its own style:

| New tab | Brings back (from) | What it shows |
|---|---|---|
| **Edge vs Cloud** | economics panel (8095), cloud baseline | The same frames through both designs: data uplinked, VLM calls, tokens, cost, and time to decision per link type (Fiber / LTE / Rural cell / Satellite / No link). It also shows frames decided with no link, the benchmark on labelled tower clips, before → after, a fleet projection and prices |
| **Mobile camera** | live camera tab (8095) | A laptop webcam or iPhone through the same detector, gate and VLM. A fire opens an incident on the map and an ALERT goes to dispatch |
| **Models** | before/after compare (8095) | Deployed detector and VLM with scores, the LoRA adapter switch (`context` / `context_v2`), a before → after table with per-source-type counts, and compare on an image (sample or upload) |
| **System** | live metrics dashboard (8090) | Node health, GPU and memory, live vLLM metrics (requests, tokens, latency p50/p95), and alert delivery with a test push |

The stats strip gets a **vs Cloud** group: data kept local, VLM calls avoided, tokens avoided, decisions with no link, and cloud cost avoided. Tabs can be linked, for example `/#tab=edge`. The compact console from v2.0.0 remains at `/console/`.

## Verified on the Nano (real models, rehearsal mode)

|---|---|---|

| Tokens | 3K | 447K (−99%) |

603 tests pass. Screens: `results/console/officer-*.png`.
