# v1.5.0-live-camera — live camera through the full pipeline, with phone alerts

**Tag:** `v1.5.0-live-camera` · **Date:** 2026-09-24 · **Status:** frozen · **Current demo release**

Adds a **Live camera** tab to the demo app: the laptop's webcam, or an iPhone through macOS Continuity Camera, streams frames to the Nano through the same pipeline a tower uses, and an ALERT is pushed to a teammate's phone with ntfy (standing in for 911 in the demo). Models and weights are unchanged from [v1.3.0-joint](v1.3.0-joint.md); the incident map from [v1.4.0-incident-map](v1.4.0-incident-map.md) is included.

## How it works

| Step | Detail |
|---|---|
| Capture | Browser `getUserMedia` on `http://localhost:8095` (secure context through the SSH tunnel); a frame every 1–2 s, ≤1280 px JPEG, one request in flight |
| Detect | Joint YOLO11s at 960 px, ~40 ms per frame on the Nano |
| Gate | Smoke in 3 frames in a row at confidence ≥ 0.4 |
| Understand | One LoRA-VLM call per event (~5.6 s measured), context JSON |
| Decide | Severity rules + growth re-check (demo pacing `--live-recheck-s 10`); one ALERT per fire (latch) |
| Deliver | ALERT → outbox → ntfy push (report + snapshot) and optional dispatch URL; offline → queued, online → sent within seconds |

**Safety for a live demo:** only test pushes are rate-limited (one per 30 s); real ALERTs are never dropped (dedupe by latch and event id; a burst guard defers more than 5 pushes a minute); queued alerts older than 10 minutes expire instead of buzzing the phone later; single-image photo alerts don't push unless `--deliver-image-alerts`. The ntfy topic is read from `~/.sentinel_alerts.env` on the Nano, never committed, logged or shown beyond its host.

## Verified on the Nano

A real D-Fire smoke-and-fire photo streamed as camera frames: gate 1/3 → 2/3 (≈40 ms each) → 3/3 → VLM "wildland" → **ALERT** with a dispatch report, 5.6 s for the event-opening frame. 514 tests pass on laptop and Nano.
