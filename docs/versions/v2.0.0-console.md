# v2.0.0-console: one system, one screen

**Tag:** `v2.0.0-console` · **Date:** 2026-09-24 · **Status:** frozen · **Current release**

The four separate servers of v1.x (demo app on 8095, metrics on 8090, incident map on 8100, the old dashboard) become one product: the **Sentinel Console**. It is one process on port 8080, with one screen and one set of shared services, and it needs no internet. The models and weights are unchanged from [v1.3.0-joint](v1.3.0-joint.md). LoRA v2 is served alongside and can be selected.

## What changed

| | v1.5 | v2.0 |
|---|---|---|
| Servers / ports | 3 servers (8090, 8095, 8100) + 3 tunnels | **1 server (8080)**, 1 tunnel, or the local network with `--lan` |
| Detector loads | one per server | **one per weights file** (shared cache + one GPU lock) |
| Uplink | a toggle per app | **one uplink** for the node |
| Alert delivery | live camera → phone; the map only simulated it | **one durable outbox** for every source (towers, mobile camera, field photos) |
| Mobile camera fire | not on the map | **opens an incident** (MONITOR as soon as it opens; ALERT when decided) |
| Edge vs cloud | an estimate panel in the demo app | **Edge vs Cloud page:** every processed frame compared, link profiles, offline-blind frames, fleet projection, optional measured cloud samples |
| Internet | map and UI local, forecast online | **nothing required:** no CDN or web fonts (enforced by a test); ALERTs queue; a local alarm (banner, tone, notification) sounds whatever the uplink state |

## Pages

**Operations** (map + incidents) · **Cameras** (towers, Run drill, mobile unit) · **Alerts** (delivery log, test push) · **Edge vs Cloud** · **Models** (scores, LoRA switch, compare on an image) · **System** (health, resources, uplink with *Test outage*). There is also an **Ask Sentinel** side panel, which runs on the device. Each page shows a few numbers; details open in a drawer or an expandable section.

## Verified on the Nano (2026-09-24, real models, rehearsal mode without phone push)

- **Tests:** 600 pass on the laptop (Python 3.13) and on the Nano (Python 3.12, Node 18).
- **Field report** (D-Fire wildfire photo): detector 60 ms, VLM 5.6 s → **ALERT**, wildland; incident opened and delivered.
- **Test outage:**
  - Mobile-camera frames: gate 1/3 → 2/3 → VLM → a MONITOR incident appears on the map while offline.
  - Field ALERT: queued (1 in the outbox) → uplink restored → sent once.
  - The incident store survived a console restart.
- **Drill** (Rainbow Fire, 91 tower frames):

  | | Edge (measured) | Cloud-only (modeled) |
  |---|---|---|
  | VLM calls | 8 | 90 |
  | Tokens | 2.2K | 151K (−99%) |
  | Data uplinked | 0 B | 6.7 MB |
  | Time to decision (LTE) | 5.5 s | 5.7 s |

## Run

```bash
cd ~/sentinel && ./scripts/start_console.sh          # or --lan to serve the local network too
# laptop: ssh -N -L 8080:localhost:8080 hp11@<nano-ip>  → http://localhost:8080
# rehearsal without buzzing the phone:  ALERTS_ENV=/dev/null ./scripts/start_console.sh
```

- **State** (incidents, frames, alert outbox) lives in `~/sentinel-state/console`, never inside the shared `~/sentinel-assets`.
- **Measured cloud samples** turn on only when `~/.cloud_vlm.env` holds `CLOUD_VLM_BASE_URL`, `CLOUD_VLM_MODEL` and `CLOUD_VLM_API_KEY`.

## Known limits

- The Edge vs Cloud ledger counts since the console started (in memory); the benchmark card shows the offline results.
- The cloud side is **modeled** (frame tokens, bytes and the netprofile link), with the edge VLM time standing in for the cloud model's compute, until measured samples are enabled.
- The mobile camera needs a secure origin: open the console on `localhost` (on the Nano or through the tunnel).
